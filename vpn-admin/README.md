# VPN Admin

Веб-админка для серверов **3x-ui**. Подключается к одной или нескольким панелям 3x-ui по их HTTP API и показывает в одном месте:

- **Обзор**: сколько всего пользователей, сколько активных, онлайн и истекших, число подписок и коннектов, общий трафик. Блок «Серверы» показывает основной сервер и под ним его узлы (дочерние серверы) со статусом, Xray, CPU, RAM, аптаймом, числом коннектов и клиентов и трафиком. Ниже — график суммарного трафика каждого узла
- **Узлы**: серверы, подключённые к главной панели 3x-ui v3 (её раздел «Узлы»). Видны статус, задержка, CPU, память, версии Xray и панели (с отметкой «Доступно обновление»), аптайм, онлайн и текущая скорость. Узлы можно добавлять, изменять, включать и выключать, проверять связь и удалять
- **Коннекты**: все inbound'ы со всех серверов (протокол, порт, транспорт, клиенты, трафик)
- **Подписки**: клиенты, сгруппированные по `subId`, со ссылками на подписку (их можно скопировать)
- **Пользователи**: все клиенты с поиском и фильтрами по статусу, серверу и онлайну
- **Серверы 3x-ui**: добавление, изменение и отключение панелей с проверкой подключения
- **VPN API Hoster**: API-ключи хостингов (DigitalOcean, OVHcloud, Scaleway, UpCloud, VDSina). Видны аккаунт, баланс и все серверы аккаунта с IP, тарифом и отметкой, подключён ли сервер к админке. Отсюда же создаётся новый сервер: админка заказывает его у хостинга, ставит 3x-ui и подключает узлом к основной панели
- **Подключения**: набор подключений (VLESS REALITY, XHTTP, WebSocket, Trojan, VMess, Shadowsocks 2022, Hysteria2, TUIC, WireGuard, AmneziaWG, MTProto), который сразу раскатывается на каждый новый сервер вместе с выбранными пользователями
- **Управление клиентами**: создание, удаление, включение и отключение, продление срока, лимиты трафика и IP, сброс трафика. Всё это работает для одного клиента, для всей подписки или для нескольких выбранных сразу.
- **Система**: текущая версия, проверка обновлений на GitHub и обновление одной кнопкой, HTTPS с сертификатом Let's Encrypt, сайт-заглушка на домене

Поддерживаются 3x-ui 2.x и 3.x. С 3x-ui v3.0.2 и новее можно подключаться по API-токену вместо логина и пароля.

Интерфейс в светлой и тёмной теме: переключатель внизу меню, по умолчанию «Системная» — тема как в ОС, меняется вместе с ней. Выбор запоминается в браузере.

## Установка одной командой

На сервере (Ubuntu/Debian):

```bash
curl -fsSL https://raw.githubusercontent.com/obotkov/lexer_space/main/vpn-admin/install.sh | sudo bash
```

Скрипт скачает из репозитория только папку `vpn-admin` в `/opt/lexer_space/vpn-admin`. Если проект уже лежит на сервере, можно запустить скрипт прямо из его папки: `sudo ./install.sh`.

Скрипт сам:
1. ставит Docker, если его нет;
2. выбирает **случайный свободный пятизначный порт** для админки и генерирует **случайные логин и пароль**. Все три значения выводятся в конце установки и хранятся в `.env`;
3. спрашивает домен. С доменом он ставит **nginx с сайтом-заглушкой** (один из 5 шаблонов, выбирается случайно) и выпускает **сертификат Let's Encrypt**. На `https://домен` открывается заглушка, а на `https://домен:порт` — админка;
4. по желанию сразу подключает первую панель 3x-ui;
5. открывает порты в ufw, если файрвол включён, собирает и запускает контейнер.

В конце будет примерно так:

```
VPN Admin запущен
  Админка:  https://vpn.example.com:48213
  Логин:    adm_k3f9q2
  Пароль:   Xw7…
  Заглушка: https://vpn.example.com  (сменить шаблон: Система → Сайт-заглушка)
```

Ответы можно передать переменными, тогда скрипт ничего не спрашивает:

```bash
sudo SITE_DOMAIN=vpn.example.com LE_EMAIL=me@example.com XUI_URL=https://127.0.0.1:2053/path XUI_API_TOKEN=токен ./install.sh
```

Остальные переменные: `ADMIN_USERNAME`, `ADMIN_PASSWORD` и `PORT` (если нужны свои значения вместо случайных), `SITE_TEMPLATE` (`coming-soon`, `maintenance`, `studio`, `cafe`, `cloud`) и `SITE=0`, чтобы не ставить nginx. При запуске без терминала сертификат выпускается автоматически, а это означает согласие с [условиями Let's Encrypt](https://letsencrypt.org/repository/).

### HTTPS

Сертификат Let's Encrypt выпускается при установке, если указан домен. Его можно выпустить и позже: *Система → HTTPS (Let's Encrypt)*. Админка открывается по `https://домен:порт`. Её порт не меняется, а порт 443 ей не нужен, поэтому всё работает рядом с VLESS Reality.
- Нужны A-запись домена на этот сервер и открытый порт 80, через который Let's Encrypt проверяет домен (HTTP-01). Если стоит nginx заглушки, проверку обслуживает он. Без nginx админка занимает порт 80 только на несколько секунд проверки.
- Кнопка «Проверить домен» сравнит A-запись с IP сервера.
- Сертификат продлевается автоматически за 30 дней до окончания: админка проверяет его каждые 12 часов. После продления она перезапускается, а nginx перечитывает сертификат. Можно продлить и вручную.
- Чтобы попробовать без лимитов Let's Encrypt, отметьте «Тестовый сертификат»: он рабочий, но браузеры ему не доверяют.
- При смене домена старый сертификат действует, пока не выпущен новый.
- Если админка стала недоступна по HTTPS, верните HTTP: `cd /opt/lexer_space/vpn-admin && sudo rm data/tls.json && sudo docker compose restart app`.

Для старых установок остаётся вариант с **Caddy на порту 443** (`DOMAIN` в `.env`): админка открывается по `https://домен` без порта, но Caddy постоянно держит порты 80 и 443.

### Сайт-заглушка

nginx на домене показывает обычный сайт, по которому не видно, что на сервере стоит VPN или админка. Шаблон меняется в *Система → Сайт-заглушка*:
- 5 встроенных вариантов с превью: «Скоро открытие», «Техработы», «Студия дизайна», «Кофейня», «IT-компания»;
- свой шаблон: вставьте HTML одним файлом. В тексте можно использовать `{{domain}}` и `{{year}}`.

Страница меняется сразу, перезапускать ничего не нужно. Заглушка открывается по HTTPS тем же сертификатом, если при установке порт 443 был свободен. Если 443 занят (например, Reality), заглушка работает только по HTTP. Конфиг nginx (`/etc/nginx/conf.d/vpn-admin-site.conf`) собирает `nginx.sh`, руками его не правьте. Добавить заглушку к уже установленной админке: `cd /opt/lexer_space/vpn-admin && sudo SITE_DOMAIN=ваш.домен ./install.sh`.

### 3x-ui на том же сервере
Контейнер работает в сети хоста, поэтому панель на этом же сервере доступна по `https://127.0.0.1:<порт>/<путь>`. Проверку TLS для такого адреса нужно отключить: сертификат панели выписан не на 127.0.0.1.

## Как подключить панель 3x-ui

В разделе **Серверы 3x-ui** нажмите «Добавить» и укажите:
- **Адрес панели** — как в адресной строке браузера, вместе с секретным путём (`webBasePath`), например `https://1.2.3.4:2053/AbCdEf`. Хвост `/panel/` можно не убирать.
- **Способ входа**:
  - **API-токен** (рекомендуется, 3x-ui v3.0.2+). Создайте его в 3x-ui: *Настройки → Безопасность → API Token*, область **Admin**. Токены с областями *Monitor* и *Node sync* не дают читать клиентов и управлять ими. Токен не истекает, не требует входа по паролю и не мешает двухфакторной авторизации.
  - **Логин и пароль** — работает на всех версиях. На 3x-ui v3 админка сама получает CSRF-токен. Если в панели включена двухфакторная авторизация, используйте API-токен.

  Пароль и токен хранятся в базе в зашифрованном виде.
- **URL подписок** — необязательно. Если поле пустое, адрес собирается из настроек подписки 3x-ui (`subURI` или домен, порт и путь).
- Снимите галочку «Проверять TLS», если у панели самоподписанный сертификат.

## Как считаются пользователи
- **Клиент** — в 3x-ui 2.x одна запись в одном inbound'е; в 3x-ui v3 — одна запись клиента, которая может быть привязана к нескольким inbound'ам.
- **Пользователь** — уникальный `subId`. Обычно у одного человека одна подписка на несколько inbound'ов. Клиенты без `subId` считаются по email.
- Статусы: *Истёк* (дата прошла), *Трафик исчерпан* (лимит выбран), *Отключён*, *Активен*.

Данные кешируются на `CACHE_TTL` секунд (по умолчанию 30). Кнопка «Обновить» запрашивает их заново.

## Управление клиентами

- **Создать**: кнопка «+ Новый клиент» на страницах «Пользователи» и «Подписки» или «+ Клиент» у конкретного коннекта. Можно выбрать несколько коннектов сразу: клиенты получат общую подписку (`subId`). В 3x-ui v3 создаётся один клиент, привязанный ко всем выбранным коннектам сервера. В 3x-ui 2.x email должен быть уникальным в пределах сервера, поэтому на втором и следующих коннектах к имени добавляется `-2`, `-3` и т. д. Чтобы добавить клиента в уже существующую подписку, укажите её `subId`.
- **В 3x-ui v3** изменения, продление и удаление применяются к клиенту целиком, то есть ко всем коннектам, к которым он привязан.
- **Изменить**: кнопка «Изменить» в строке пользователя, «Управлять» у подписки (действие применится ко всем её клиентам) или галочки в таблице пользователей и «Действия с выбранными».
- **Продлить**: срок прибавляется к текущей дате окончания, а если он уже истёк — к сегодняшней. Бессрочных клиентов продление не затрагивает. Продлённый клиент автоматически включается.
- **Сбросить трафик**: обнуляет счётчик; 3x-ui при этом снова включает клиента, если он был отключён за превышение лимита.
- **Удалить**: удаляет клиента из 3x-ui безвозвратно. 3x-ui не даёт удалить последнего клиента в коннекте.

Поддерживаемые протоколы: VLESS, VMess, Trojan и Shadowsocks, включая 2022.

## Узлы

В 3x-ui v3 главная панель может управлять другими серверами с 3x-ui (узлами): она синхронизирует на них коннекты и клиентов и раз в несколько секунд опрашивает их состояние. Раздел **Узлы** показывает этот список для всех подключённых v3-панелей:
- сверху сводка: всего узлов, в сети, не в сети, средняя задержка, клиентов онлайн;
- в таблице: включение, имя, адрес (скрыт, открывается значком глаза), статус с текстом ошибки, CPU, память, версии Xray и панели, аптайм, задержка, онлайн и текущая скорость сети (↓/↑ в секунду). Если на узле версия 3x-ui старше последнего релиза на GitHub, рядом стоит «Доступно обновление»;
- действия: проверить связь, изменить, удалить.

**Добавить узел**: укажите адрес, порт и путь (`webBasePath`) панели узла и её API-токен. Токен создаётся на самом узле: *Настройки → Безопасность → API Token*. Кнопка «Проверить соединение» опросит узел до сохранения. При сохранении главная панель сама проверяет связь и не добавит недоступный узел. Коннекты узла можно импортировать все или только выбранные.

Для автоматизации тот же шаг доступен через API админки: `POST /api/nodes` с `panel_id` главной панели, `name`, `address`, `port`, `base_path`, `api_token` (нужна сессия администратора).

Трафик узла на **Обзоре** — это сумма трафика коннектов, которые главная панель получила с этого узла (у каждого такого коннекта в 3x-ui v3 есть `nodeId`), с момента последнего сброса счётчиков. В строке основного сервера — трафик только его собственных коннектов; полная сумма вместе с узлами видна в подсказке.

В 3x-ui 2.x узлов нет: для таких панелей раздел покажет пояснение.

## VPN API Hoster

Раздел для API-ключей хостингов, через которые админка будет заказывать новые серверы под VPN. Сейчас поддерживаются:

| Хостинг | Что нужно | Где взять |
|---|---|---|
| DigitalOcean | Personal Access Token | [Control Panel → API → Tokens](https://cloud.digitalocean.com/account/api/tokens). Для просмотра хватит Read, для создания серверов нужен Full Access |
| OVHcloud | регион API, Application Key, Application Secret, Consumer Key. Регион — по стране регистрации аккаунта: Европа — eu.api.ovh.com, США — api.us.ovhcloud.com, Канада и остальной мир — ca.api.ovh.com. Если ключ создан на другом API, админка подскажет, какой регион выбрать. Consumer Key должен иметь права хотя бы GET/POST/DELETE на `/cloud/*` (ссылка в форме запрашивает GET/POST/PUT/DELETE на `/*`); при проверке админка читает права ключа и называет недостающие |
| Scaleway | Project ID и Secret Key | Console → IAM → API keys → Generate API key (Secret Key показывается один раз); у ключа нужны права на Instances и Block Storage. Project ID — в Project settings. SSH-ключи проекта Scaleway добавляет на новые серверы сам |
| UpCloud | API-токен (`ucat_…`) и, по желанию, свой открытый SSH-ключ | Control Panel → Account → API Tokens (токен показывается один раз, срок до года). SSH-ключ указывается в настройках аккаунта в админке: им можно будет входить на новые серверы |
| VDSina | сайт аккаунта (vdsina.com — цены в $, vdsina.ru — в ₽) и API-токен | в панели VDSina, в данных пользователя аккаунта; токен меняется при смене пароля. У vdsina.com и vdsina.ru отдельные аккаунты: если токен от другого сайта, админка подскажет | все три ключа сразу выдаёт [createToken](https://eu.api.ovh.com/createToken/?GET=/*&POST=/*&PUT=/*&DELETE=/*) (для CA и US ссылка своя, она есть в форме). Срок действия — Unlimited |

При сохранении ключ сразу проверяется: неработающий ключ админка не сохранит. Ключи хранятся в базе зашифрованными и наружу не отдаются; при изменении аккаунта секретные поля можно оставить пустыми, тогда останутся прежние.

Для каждого аккаунта видны логин, баланс и список серверов. Баланс показан так, как его отдаёт API хостинга: у VDSina и UpCloud — деньги на счёте; у DigitalOcean, OVHcloud и Scaleway, которые выставляют счёт после месяца, — предоплата или остаток ваучеров, расход за текущий месяц и долг, если он есть. Для баланса DigitalOcean токену нужно право billing:read, ключу Scaleway — набор прав BillingReadOnly; без них админка пишет об этом рядом с аккаунтом. Серверы в списке: дроплеты DigitalOcean, VPS и инстансы Public Cloud OVHcloud. Для сервера показаны статус, регион, тариф, IP и дата создания. Если IP совпадает с адресом основного сервера 3x-ui или одного из его узлов, стоит отметка «в админке».

### Создание нового сервера

Кнопка **«+ Создать сервер»** у аккаунта хостинга заказывает сервер и превращает его в узел основной панели 3x-ui v3 без ручных шагов:

1. **Заказ сервера.** Выберите регион, тариф, SSH-ключ из аккаунта, адрес панели узла (IP сервера или свой домен) и основную панель. У каждого тарифа видна цена в час и в месяц (без налогов): у DigitalOcean — из API, у OVHcloud — из публичного прайс-листа в валюте аккаунта; месяц у OVHcloud считается как 730 часов, рядом показана цена тарифа с помесячной оплатой. У DigitalOcean создаётся дроплет, у OVHcloud — инстанс Public Cloud в выбранном проекте (почасовая оплата; обычные VPS OVH через API можно только заказать с оплатой, поэтому они не поддерживаются). Система — Ubuntu 24.04.
2. **Запуск.** Админка ждёт, пока сервер запустится и получит публичный IP.
3. **Установка 3x-ui.** Для каждого сервера админка создаёт свой SSH-ключ. Хостингу передаётся только маленький скрипт cloud-init, который пускает этот ключ под root (VDSina, у которой cloud-init нет, получает ключ при заказе). Затем админка заходит на сервер по SSH и сама выполняет установку: Docker и официальный образ `ghcr.io/mhsanaei/3x-ui`, BBR, сайт-заглушку, сертификат Let's Encrypt через acme.sh и настройку панели командой `x-ui setting`. Порт, секретный путь, логин и пароль админка генерирует сама; порт подписки тоже меняется со стандартного 2096 на случайный пятизначный (у `x-ui setting` для него нет параметра, поэтому он записывается в базу панели до первого запуска) и виден в карточке сервера. В конце установки ключ админки удаляется с сервера (закрытая часть остаётся в админке в зашифрованном виде — она понадобится при переустановке ОС).
   - **Сайт-заглушка** — тот же набор шаблонов, что у заглушки админки (или ваш свой шаблон из раздела «Система»), выбирается в форме. Её показывает nginx в Docker на порту 80 по IP и домену; порт 443 остаётся свободным для VPN. Тот же nginx отвечает на проверки Let's Encrypt, поэтому сертификат продлевается, не останавливая заглушку.
   - **Домен:** IP сервера появляется в журнале задания после запуска — создайте на него A-запись. Скрипт ждёт её до 20 минут (проверяет через DNS-over-HTTPS Cloudflare) и выпускает сертификат на домен.
   - **IP** (или если A-запись не появилась): короткий сертификат Let's Encrypt на IP (около 6 дней), acme.sh продлевает его по cron каждые 3 дня и перезапускает контейнер 3x-ui.
   - Если Let's Encrypt отказал, панель остаётся на самоподписанном сертификате, который админка выпустила заранее.
4. **Подключение узлом.** Админка смотрит, каким сертификатом отвечает панель: сертификат Let's Encrypt узел получает с проверкой TLS «verify» (по домену или IP), самоподписанный — «pin» с его отпечатком; любой другой сертификат останавливает задание. Затем админка входит в панель узла, создаёт API-токен со scope `node-admin` и добавляет узел в основную панель.
5. **Подключения.** Админка создаёт на узле подключения, включённые в разделе «Подключения» (см. ниже), и добавляет в них выбранных пользователей. Галочка в форме создания сервера позволяет этот шаг пропустить.

**Scaleway**: сервер создаётся выключенным с образом Ubuntu 24.04 из Marketplace и отдельным routed IPv4, получает скрипт cloud-init и только потом включается. Цены за час и за месяц приходят из API Scaleway; публичный IPv4 и диск оплачиваются отдельно. «Удалить сервер у хостинга» удаляет вместе с сервером его блочный диск и IP, иначе они продолжали бы стоить денег. У новых организаций Scaleway есть квоты: STARDUST1 — не больше 1 сервера на организацию, многие типы (DEV1-XL, GP1, PRO2, POP2) доступны только после подтверждения личности; если хостинг отказал по квоте, админка показывает, какая квота исчерпана и что сделать.

**UpCloud** создаёт серверы с cloud-init только со входом по SSH-ключу, поэтому админка передаёт свой ключ (установка удаляет его с сервера) и, если задан, ваш ключ из настроек аккаунта. Цены приходят в центах за час, месяц ограничен 28 днями (672 часа). Диск сервера клонируется из образа Ubuntu и не может быть меньше него: админка берёт Ubuntu 24.04, а если она не помещается на диск тарифа — 22.04. Тарифы, на диск которых не помещается ни один из образов (например, 10 ГБ у DEV-1xCPU-1GB-10GB, если образы больше), в форме не показываются. При удалении сервер останавливается и удаляется вместе с дисками.

**VDSina** не поддерживает cloud-init, поэтому ключ админки регистрируется в аккаунте VDSina и передаётся при заказе сервера; после установки админка добавляет root выбранный в форме SSH-ключ из аккаунта и удаляет свой ключ с сервера и из аккаунта VDSina. Цены VDSina посуточные; в форме они пересчитаны в цену за час и за месяц (30 дней).

**Домен из Cloudflare.** В блоке «DNS: Cloudflare» на странице VPN API Hoster подключите API-токен Cloudflare (dash.cloudflare.com → My Profile → API Tokens → Create Token → шаблон «Edit zone DNS»: права Zone → DNS → Edit и Zone → Zone → Read, в Zone Resources — нужные домены). Тогда в форме создания сервера появится вариант «Домен Cloudflare»: имя (по умолчанию — имя сервера) и домен из аккаунта. Как только сервер получит IP, админка создаёт A-запись без проксирования (через прокси Cloudflare VPN не работает), и скрипт установки сразу выпускает на этот домен сертификат Let's Encrypt. Если такое имя в Cloudflare уже занято, заказ не начнётся. При переустановке новым сервером запись переводится на новый IP, при удалении сервера — удаляется.

**Удаление сервера.** Кнопка «Удалить сервер» на карточке готового сервера удаляет его у хостинга. Узел без инбаундов админка убирает из основной панели. Узел с инбаундами 3x-ui удалить не даёт, поэтому админка его только выключает: инбаунды и клиенты остаются, пока вы их не удалите или не перенесёте, после этого узел можно удалить на странице «Узлы».

**Переустановка с нуля.** Кнопка «Переустановить с нуля» на карточке сервера ставит 3x-ui заново и переключает на новую установку тот же узел основной панели. Инбаунды и клиенты хранятся в основной панели и сами переносятся на новую установку.

- **Тот же сервер** (DigitalOcean, OVHcloud, VDSina — у них переустановка ОС есть в API): 1) хостинг стирает диск и ставит Ubuntu заново (DigitalOcean — `rebuild`, OVHcloud — `reinstall`, VDSina — `server.reinstall`), IP и тариф сохраняются; 2) скрипт cloud-init снова пускает ключ админки (VDSina получает его вместе с переустановкой), и админка выполняет штатную установку, как у нового сервера: 3x-ui с новыми логином и паролем, сайт-заглушка (шаблон можно сменить в окне переустановки), сертификат. Пока идёт переустановка, VPN на сервере не работает. Серверы DigitalOcean и OVHcloud, созданные версиями до 0.17.0, после переустановки ОС запускают свой прежний скрипт: 3x-ui встаёт с прежними логином и паролем и без заглушки; для штатной установки выберите «Новый сервер».
- **Новый сервер** (Scaleway и UpCloud, у которых переустановки ОС в API нет, а у остальных — по выбору в окне): админка заказывает новый сервер с тем же хостингом, регионом и адресом (тариф можно сменить), ставит 3x-ui, переключает на него узел и удаляет старый сервер. IP меняется: клиенты с подпиской получат новый адрес при обновлении подписки, A-запись домена нужно перенаправить на новый IP. Новый сервер заказывается до удаления старого, поэтому тариф, который хостинг разрешает держать только в одном экземпляре (STARDUST1 у Scaleway), нельзя переустановить на тот же тариф — админка предупредит и предложит выбрать другой. Если хостинг отказал в заказе, старый сервер продолжает работать, а новая переустановка заменит неудачную попытку.

Обычно всё занимает 5–10 минут; прогресс по шагам и журнал видны в блоке «Новые серверы». Если админку перезапустить посреди процесса, задание продолжится с того же шага. При ошибке можно нажать «Повторить» (с шага, где случилась ошибка) или «Удалить сервер у хостинга», чтобы не платить за него. Адрес, логин и пароль панели нового узла хранятся в админке (пароль зашифрован) и открываются кнопкой «показать». Журнал установки на самом сервере: `/var/log/vpn-admin-node.log`.

## Подключения

Раздел **«Подключения»** — список подключений, которые получает каждый новый сервер сразу после того, как станет узлом основной панели. Набор и настройки взяты из [3X-UI KIT](https://github.com/itsnotkubrick/3X-UI_KIT) и [3x-ui-pro](https://github.com/mozaroc/3x-ui-pro). При первом открытии раздела в нём появляется стандартный набор KIT, все подключения выключены. Включите нужные; их можно настроить, переименовать, переставить, а также добавить свои.

| Тип | Протокол 3x-ui | Порт по умолчанию | Настройки |
|---|---|---|---|
| VLESS REALITY | vless, TCP | 443 | сайт маскировки (SNI; несколько через запятую — каждому серверу случайный), fingerprint, flow, число shortId |
| VLESS XHTTP + REALITY | vless, TCP | случайный | сайт маскировки, fingerprint, режим XHTTP, путь |
| VLESS WebSocket + TLS | vless, TCP | случайный | путь, fingerprint |
| Trojan gRPC + TLS | trojan, TCP | случайный | имя сервиса, fingerprint |
| VMess WebSocket + TLS | vmess, TCP | случайный | путь, fingerprint |
| Shadowsocks 2022 | shadowsocks, TCP+UDP | случайный | шифрование |
| Hysteria2 | hysteria, UDP | 443 | ответ сайтом-заглушкой на посторонние запросы |
| TUIC v5 | tuic, UDP | случайный | управление перегрузкой |
| WireGuard | wireguard, UDP | случайный | MTU, подсеть |
| AmneziaWG (классический и 3.1) | amneziawg, UDP | случайный | параметры маскировки, подсеть, DNS |
| MTProto (Telegram) | mtproto, TCP | случайный | домен FakeTLS |

Как это работает:

- **Подключения на сервере.** Каждое подключение — инбаунд основной панели, привязанный к узлу. Ключи REALITY, shortId, пути, имена сервисов, пароли Shadowsocks и ключи WireGuard/AmneziaWG у каждого сервера свои. TLS-подключения (WebSocket, gRPC, Hysteria2, TUIC) используют сертификат Let's Encrypt сервера; если сервер остался на самоподписанном сертификате, в ссылки попадает его отпечаток. В названии `{server}` заменяется именем сервера.
- **Порты.** «Случайный» — свободный пятизначный порт на каждом сервере. Свой порт берётся, если он свободен; если его занимает панель, подписка, заглушка на 80 или другое подключение, подключение получит случайный. TCP и UDP считаются отдельно: REALITY и Hysteria2 вместе живут на 443. Порты фиксируются при заказе сервера, и установка открывает их в ufw, если он включён.
- **Пользователи.** В блоке «Кого добавлять» выберите всех пользователей основной панели, отмеченных или никого. Учётные данные для каждого протокола 3x-ui создаёт сам, а подписки пользователей сразу показывают новый сервер. Тем, у кого не задан flow, включается `xtls-rprx-vision`: в 3x-ui v3 flow хранится у пользователя, и 3x-ui применяет его только к REALITY по TCP.
- **Ограничения 3x-ui v3.** У пользователя один пароль и один адрес WireGuard на все подключения, а Xray узла собирает конфиг из этой общей записи. Поэтому:
  - в Shadowsocks 2022 попадают только пользователи без пароля или с паролем, который подходит как ключ шифрования. Иначе Xray на узле не запустится. Всем, кого создаёт админка, сразу задаётся такой пароль (ключ aes-128 подходит и Trojan);
  - в WireGuard/AmneziaWG попадают только пользователи без адреса или с адресом из подсети подключения. Поэтому у WireGuard и классического AmneziaWG по умолчанию одна подсеть, а AmneziaWG 3.1 получит только тех, у кого адреса ещё нет.
  
  Кого пропустили и почему, видно в журнале задания.
- **Уже работающие серверы.** Кнопка «Раскатать подключения» на карточке сервера добавляет включённые подключения, которых на нём ещё нет; существующие инбаунды узла она не трогает. На переустановленном сервере подключения не создаются заново: инбаунды остаются в основной панели и переезжают на новую установку.
- **Проверка сайта маскировки.** Кнопка «Проверить» у SNI проверяет с сервера админки, что сайт отвечает по TLS 1.3 с HTTP/2. Без этого REALITY не работает.

## Обновление

Раздел **Система** показывает текущую версию и проверяет GitHub (раз в 30 минут или по кнопке). Версия сравнивается по хешу папки `vpn-admin` в git, поэтому коммиты в другие папки репозитория не считаются обновлением. Если есть новая версия, видно список изменений и кнопку **«Обновить сейчас»**.

Как это работает: контейнер не может пересобрать сам себя, поэтому кнопка кладёт файл `data/update.request`. Его замечает systemd-юнит `vpn-admin-update.path` на хосте (его ставит `install.sh`) и запускает `update.sh`: `git pull`, сборку и перезапуск контейнера. Ход и журнал обновления видны в админке. VPN и сама 3x-ui при этом не перезапускаются.

Вручную:

```bash
sudo /opt/lexer_space/vpn-admin/update.sh
```

Если админка была установлена до появления автообновления, включите его один раз: `cd /opt/lexer_space/vpn-admin && sudo git pull && sudo ./install.sh`.

Источник обновлений задаётся в `.env`: `UPDATE_REPO`, `UPDATE_BRANCH`, `UPDATE_PATH`.

## Обслуживание

```bash
cd /opt/lexer_space/vpn-admin
docker compose logs -f app      # логи
docker compose restart app      # перезапуск
sudo ./update.sh                # обновление (git pull + пересборка, настройки сохраняются)
journalctl -u vpn-admin-update  # журнал обновлений, запущенных из админки
```

Настройки лежат в `.env`, база — в `data/`. Не меняйте `SECRET_KEY` после установки: без него сохранённые пароли 3x-ui не расшифровать.

## Разработка

```bash
# backend
cd backend && python -m venv .venv && .venv/bin/pip install -r requirements.txt
ADMIN_PASSWORD=dev SECRET_KEY=dev-secret-key-1234 DATA_DIR=./data .venv/bin/uvicorn app.main:app --reload --port 8000

# frontend (проксирует /api на :8000)
cd frontend && npm install && npm run dev
```
