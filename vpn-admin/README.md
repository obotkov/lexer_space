# VPN Admin

Веб-админка для серверов **3x-ui**. Подключается к одной или нескольким панелям 3x-ui по их HTTP API и показывает в одном месте:

- **Обзор**: сколько всего пользователей, сколько активных, онлайн и истекших, число подписок и узлов, общий трафик, состояние серверов (Xray, CPU, RAM, аптайм)
- **Узлы**: все inbound'ы со всех серверов (протокол, порт, транспорт, клиенты, трафик)
- **Подписки**: клиенты, сгруппированные по `subId`, со ссылками на подписку (их можно скопировать)
- **Пользователи**: все клиенты с поиском и фильтрами по статусу, серверу и онлайну
- **Серверы 3x-ui**: добавление, изменение и отключение панелей с проверкой подключения
- **Управление клиентами**: создание, удаление, включение и отключение, продление срока, лимиты трафика и IP, сброс трафика. Всё это работает для одного клиента, для всей подписки или для нескольких выбранных сразу.
- **Система**: текущая версия, проверка обновлений на GitHub и обновление одной кнопкой, HTTPS с сертификатом Let's Encrypt, сайт-заглушка на домене

Поддерживаются 3x-ui 2.x и 3.x. С 3x-ui v3.0.2 и новее можно подключаться по API-токену вместо логина и пароля.

## Установка одной командой

На сервере (Ubuntu/Debian):

```bash
curl -fsSL https://raw.githubusercontent.com/obotkov/lexer_space/main/vpn-admin/install.sh | sudo bash
```

Скрипт скачает из репозитория только папку `vpn-admin` в `/opt/lexer_space/vpn-admin`. Если проект уже лежит на сервере, можно запустить скрипт прямо из его папки: `sudo ./install.sh`.

Скрипт сам:
1. ставит Docker, если его нет;
2. выбирает **случайный свободный пятизначный порт** для админки и генерирует **случайные логин и пароль**. Все три значения выводятся в конце установки и хранятся в `.env`;
3. спрашивает домен. С доменом он ставит **nginx с сайтом-заглушкой** (один из 5 шаблонов, выбирается случайно) и выпускает **сертификат Let's Encrypt**. На `https://домен` открывается заглушка, а на `https://домен:порт` — админка;
4. по желанию сразу подключает первую панель 3x-ui;
5. открывает порты в ufw, если файрвол включён, собирает и запускает контейнер.

В конце будет примерно так:

```
VPN Admin запущен
  Админка:  https://vpn.example.com:48213
  Логин:    adm_k3f9q2
  Пароль:   Xw7…
  Заглушка: https://vpn.example.com  (сменить шаблон: Система → Сайт-заглушка)
```

Ответы можно передать переменными, тогда скрипт ничего не спрашивает:

```bash
sudo SITE_DOMAIN=vpn.example.com LE_EMAIL=me@example.com XUI_URL=https://127.0.0.1:2053/path XUI_API_TOKEN=токен ./install.sh
```

Остальные переменные: `ADMIN_USERNAME`, `ADMIN_PASSWORD` и `PORT` (если нужны свои значения вместо случайных), `SITE_TEMPLATE` (`coming-soon`, `maintenance`, `studio`, `cafe`, `cloud`) и `SITE=0`, чтобы не ставить nginx. При запуске без терминала сертификат выпускается автоматически, а это означает согласие с [условиями Let's Encrypt](https://letsencrypt.org/repository/).

### HTTPS

Сертификат Let's Encrypt выпускается при установке, если указан домен. Его можно выпустить и позже: *Система → HTTPS (Let's Encrypt)*. Админка открывается по `https://домен:порт`. Её порт не меняется, а порт 443 ей не нужен, поэтому всё работает рядом с VLESS Reality.
- Нужны A-запись домена на этот сервер и открытый порт 80, через который Let's Encrypt проверяет домен (HTTP-01). Если стоит nginx заглушки, проверку обслуживает он. Без nginx админка занимает порт 80 только на несколько секунд проверки.
- Кнопка «Проверить домен» сравнит A-запись с IP сервера.
- Сертификат продлевается автоматически за 30 дней до окончания: админка проверяет его каждые 12 часов. После продления она перезапускается, а nginx перечитывает сертификат. Можно продлить и вручную.
- Чтобы попробовать без лимитов Let's Encrypt, отметьте «Тестовый сертификат»: он рабочий, но браузеры ему не доверяют.
- При смене домена старый сертификат действует, пока не выпущен новый.
- Если админка стала недоступна по HTTPS, верните HTTP: `cd /opt/lexer_space/vpn-admin && sudo rm data/tls.json && sudo docker compose restart app`.

Для старых установок остаётся вариант с **Caddy на порту 443** (`DOMAIN` в `.env`): админка открывается по `https://домен` без порта, но Caddy постоянно держит порты 80 и 443.

### Сайт-заглушка

nginx на домене показывает обычный сайт, по которому не видно, что на сервере стоит VPN или админка. Шаблон меняется в *Система → Сайт-заглушка*:
- 5 встроенных вариантов с превью: «Скоро открытие», «Техработы», «Студия дизайна», «Кофейня», «IT-компания»;
- свой шаблон: вставьте HTML одним файлом. В тексте можно использовать `{{domain}}` и `{{year}}`.

Страница меняется сразу, перезапускать ничего не нужно. Заглушка открывается по HTTPS тем же сертификатом, если при установке порт 443 был свободен. Если 443 занят (например, Reality), заглушка работает только по HTTP. Конфиг nginx (`/etc/nginx/conf.d/vpn-admin-site.conf`) собирает `nginx.sh`, руками его не правьте. Добавить заглушку к уже установленной админке: `cd /opt/lexer_space/vpn-admin && sudo SITE_DOMAIN=ваш.домен ./install.sh`.

### 3x-ui на том же сервере
Контейнер работает в сети хоста, поэтому панель на этом же сервере доступна по `https://127.0.0.1:<порт>/<путь>`. Проверку TLS для такого адреса нужно отключить: сертификат панели выписан не на 127.0.0.1.

## Как подключить панель 3x-ui

В разделе **Серверы 3x-ui** нажмите «Добавить» и укажите:
- **Адрес панели** — как в адресной строке браузера, вместе с секретным путём (`webBasePath`), например `https://1.2.3.4:2053/AbCdEf`. Хвост `/panel/` можно не убирать.
- **Способ входа**:
  - **API-токен** (рекомендуется, 3x-ui v3.0.2+). Создайте его в 3x-ui: *Настройки → Безопасность → API Token*, область **Admin**. Токены с областями *Monitor* и *Node sync* не дают читать клиентов и управлять ими. Токен не истекает, не требует входа по паролю и не мешает двухфакторной авторизации.
  - **Логин и пароль** — работает на всех версиях. На 3x-ui v3 админка сама получает CSRF-токен. Если в панели включена двухфакторная авторизация, используйте API-токен.

  Пароль и токен хранятся в базе в зашифрованном виде.
- **URL подписок** — необязательно. Если поле пустое, адрес собирается из настроек подписки 3x-ui (`subURI` или домен, порт и путь).
- Снимите галочку «Проверять TLS», если у панели самоподписанный сертификат.

## Как считаются пользователи
- **Клиент** — в 3x-ui 2.x одна запись в одном inbound'е; в 3x-ui v3 — одна запись клиента, которая может быть привязана к нескольким inbound'ам.
- **Пользователь** — уникальный `subId`. Обычно у одного человека одна подписка на несколько inbound'ов. Клиенты без `subId` считаются по email.
- Статусы: *Истёк* (дата прошла), *Трафик исчерпан* (лимит выбран), *Отключён*, *Активен*.

Данные кешируются на `CACHE_TTL` секунд (по умолчанию 30). Кнопка «Обновить» запрашивает их заново.

## Управление клиентами

- **Создать**: кнопка «+ Новый клиент» на страницах «Пользователи» и «Подписки» или «+ Клиент» у конкретного узла. Можно выбрать несколько узлов сразу: клиенты получат общую подписку (`subId`). В 3x-ui v3 создаётся один клиент, привязанный ко всем выбранным узлам сервера. В 3x-ui 2.x email должен быть уникальным в пределах сервера, поэтому на втором и следующих узлах к имени добавляется `-2`, `-3` и т. д. Чтобы добавить клиента в уже существующую подписку, укажите её `subId`.
- **В 3x-ui v3** изменения, продление и удаление применяются к клиенту целиком, то есть ко всем узлам, к которым он привязан.
- **Изменить**: кнопка «Изменить» в строке пользователя, «Управлять» у подписки (действие применится ко всем её клиентам) или галочки в таблице пользователей и «Действия с выбранными».
- **Продлить**: срок прибавляется к текущей дате окончания, а если он уже истёк — к сегодняшней. Бессрочных клиентов продление не затрагивает. Продлённый клиент автоматически включается.
- **Сбросить трафик**: обнуляет счётчик; 3x-ui при этом снова включает клиента, если он был отключён за превышение лимита.
- **Удалить**: удаляет клиента из 3x-ui безвозвратно. 3x-ui не даёт удалить последнего клиента в узле.

Поддерживаемые протоколы: VLESS, VMess, Trojan и Shadowsocks, включая 2022.

## Обновление

Раздел **Система** показывает текущую версию и проверяет GitHub (раз в 30 минут или по кнопке). Версия сравнивается по хешу папки `vpn-admin` в git, поэтому коммиты в другие папки репозитория не считаются обновлением. Если есть новая версия, видно список изменений и кнопку **«Обновить сейчас»**.

Как это работает: контейнер не может пересобрать сам себя, поэтому кнопка кладёт файл `data/update.request`. Его замечает systemd-юнит `vpn-admin-update.path` на хосте (его ставит `install.sh`) и запускает `update.sh`: `git pull`, сборку и перезапуск контейнера. Ход и журнал обновления видны в админке. VPN и сама 3x-ui при этом не перезапускаются.

Вручную:

```bash
sudo /opt/lexer_space/vpn-admin/update.sh
```

Если админка была установлена до появления автообновления, включите его один раз: `cd /opt/lexer_space/vpn-admin && sudo git pull && sudo ./install.sh`.

Источник обновлений задаётся в `.env`: `UPDATE_REPO`, `UPDATE_BRANCH`, `UPDATE_PATH`.

## Обслуживание

```bash
cd /opt/lexer_space/vpn-admin
docker compose logs -f app      # логи
docker compose restart app      # перезапуск
sudo ./update.sh                # обновление (git pull + пересборка, настройки сохраняются)
journalctl -u vpn-admin-update  # журнал обновлений, запущенных из админки
```

Настройки лежат в `.env`, база — в `data/`. Не меняйте `SECRET_KEY` после установки: без него сохранённые пароли 3x-ui не расшифровать.

## Используемое API 3x-ui

Общее для всех версий:

| Метод | Путь | Зачем |
|---|---|---|
| POST | `/login` | сессия (cookie), если вход по паролю |
| GET | `/panel/api/inbounds/list` | inbound'ы и трафик |
| GET / POST | `/panel/api/server/status` или `/server/status` | состояние сервера |

3x-ui v3 (авторизация `Authorization: Bearer <токен>` или cookie + `X-CSRF-Token` из `GET /csrf-token`):

| Метод | Путь | Зачем |
|---|---|---|
| GET | `/panel/api/clients/list`, `/panel/api/clients/get/{email}` | клиенты и их узлы |
| POST | `/panel/api/clients/add` | создание (сразу на несколько inbound'ов) |
| POST | `/panel/api/clients/update/{email}` | изменение, вкл/выкл, продление |
| POST | `/panel/api/clients/del/{email}` | удаление |
| POST | `/panel/api/clients/resetTraffic/{email}` | сброс трафика |
| POST | `/panel/api/clients/onlines`, `/panel/api/setting/all` | кто онлайн, настройки подписок |

3x-ui 2.x:

| Метод | Путь | Зачем |
|---|---|---|
| GET | `/panel/api/inbounds/get/{id}` | актуальные данные клиента перед изменением |
| POST | `/panel/api/inbounds/addClient` | создание клиента |
| POST | `/panel/api/inbounds/updateClient/{uuid\|password\|email}` | изменение, вкл/выкл, продление |
| POST | `/panel/api/inbounds/{id}/delClient/{uuid\|password\|email}` | удаление |
| POST | `/panel/api/inbounds/{id}/resetClientTraffic/{email}` | сброс трафика |
| POST | `/panel/api/inbounds/onlines`, `/panel/setting/all` | кто онлайн, настройки подписок |

## Разработка

```bash
# backend
cd backend && python -m venv .venv && .venv/bin/pip install -r requirements.txt
ADMIN_PASSWORD=dev SECRET_KEY=dev-secret-key-1234 DATA_DIR=./data .venv/bin/uvicorn app.main:app --reload --port 8000

# frontend (проксирует /api на :8000)
cd frontend && npm install && npm run dev
```

Стек: FastAPI, httpx, SQLite, React, Vite, TypeScript, Docker, Caddy.
